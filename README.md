# Маркетинговая аналитика спортивного магазина

Личный аналитический проект: подготовка данных о покупках, оценка маркетинговых кампаний, сегментация клиентов и прогноз вероятности покупки конкретного товара.

Исследование охватывает **104 437 клиентов** и **780 117 строк покупок** за **59 дней**. По результатам анализа подготовлены рекомендации по персональным предложениям и план проверки новой кампании.

**[Аналитический отчёт](analysis_report.pdf)** · **[Презентация](presentation.pdf)** · **[Python-код](project_analysis.py)**

## Бизнес-задача

Оценить, что можно заключить об эффективности персональных скидок и рекламы, выделить группы покупателей с разными предпочтениями и определить аудиторию для следующей коммуникации.

## Стек

Python, SQL, SQLite, pandas, NumPy, SciPy, scikit-learn, Matplotlib, threadpoolctl.

## Что сделано

1. Объединены таблицы SQLite и CSV. Проверены ключи соединения, пропуски, дубликаты и аномальные значения. Нормализованы названия товаров и цвета.
2. Построены и сравнены модели для восстановления отсутствующего признака пола клиента. Известные и восстановленные значения разделены отдельным индикатором.
3. Проведён анализ персональной рассылки: критерий Уэлча, доверительные интервалы, bootstrap и проверка исходной сопоставимости групп.
4. Проанализирована динамика продаж во время кампании на билбордах с учётом ограничений географических данных.
5. Выбраны три сегмента KMeans, описаны их товарные предпочтения и поведение при скидках.
6. Построена модель вероятности покупки для пар «клиент и товар». Признаки рассчитываются по истории до прогнозируемого периода, оценка выполнена на более позднем временном окне.
7. Подготовлены итоговая таблица, прогнозы, отчёт и презентация для бизнеса.

## Основные результаты

| Направление | Результат | Практический вывод |
|---|---|---|
| Персональная рассылка | Во время кампании выручка на клиента у получателей выше на 18,6%, но до кампании разница уже составляла 40,9% | Масштабирование скидки требует нового эксперимента с сопоставимыми группами |
| Проверка изменения выручки | Разница изменений дневной выручки около −102 ден. ед., p = 0,153 | Дополнительный положительный эффект этим расчётом не подтверждается |
| Сегментация | Три сегмента: обувь, одежда и инвентарь | Предложения стоит проверять с учётом товарных предпочтений сегментов |
| Модель покупки | ROC AUC = 0,7713, Average Precision = 0,05601 на тесте по времени | Модель можно использовать для ранжирования аудитории и выбора товара |
| Отбор аудитории | В городе 1188 верхние 10% пар «клиент и товар» по прогнозу содержат 47,6% покупок выбранных товаров на тесте | Есть основание проверить приоритетный отбор в новой кампании |

Доля положительных пар на тесте составляет 0,00393. Каталог модели ограничен восемью товарами. Метрики ранжирования описывают прошлый период; результат будущей рассылки должен проверяться отдельным экспериментом.

## Как запустить

Рекомендуется **Python 3.12**. Выполняйте команды из корня скачанного репозитория.

### 1 Подготовить окружение

Linux, WSL или macOS с установленным Python 3.12:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell с установленным Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Установка библиотек:

```bash
python -m pip install -r requirements.txt
```

В `requirements.txt` зафиксированы версии библиотек для публикации проекта. Полный пересчёт в этом окружении требует исходных данных.

### 2 Подготовить входные файлы

Поместите исходные файлы в каталог `data` в корне репозитория:

| Локальный путь | Назначение |
|---|---|
| `data/data.zip` | Исходный архив с базой магазина и дополнительными таблицами |
| `data/personal_data.csv` | Дополнительные профили клиентов |

Внутри исходного `data.zip` должны сохраняться пути `result_data/shop_database.db`, `result_data/personal_data.csv.gz`, `result_data/ids_first_company_positive.txt` и `result_data/ids_first_company_negative.txt`. Скрипт распаковывает архив самостоятельно.

### 3 Выполнить анализ

```bash
python project_analysis.py --data data/data.zip --personal data/personal_data.csv --out results
```

Каталог `results` создаётся при выполнении. В него сохраняются проверки качества, промежуточные таблицы, метрики моделей, графики, сегменты и прогнозы. Для просмотра параметров:

```bash
python project_analysis.py --help
```

## Ограничения

- Группы первой кампании различались до её начала. Наблюдаемая разница выручки требует осторожной интерпретации.
- Прогноз вероятности покупки используется для ранжирования; дополнительный эффект коммуникации нужно измерять экспериментом.
- В исходных данных нет ID заказа и количества единиц в строке, поэтому частота означает число строк покупок, а средняя стоимость относится к строке покупки.
- Город и страна в профиле описывают место рождения. Для географического таргетинга нужно уточнять актуальное проживание.
- Себестоимость, стоимость персональной скидки и расходы на коммуникации отсутствуют. Прибыль и ROI не рассчитаны.
